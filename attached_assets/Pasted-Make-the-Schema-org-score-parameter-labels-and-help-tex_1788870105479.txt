Make the Schema.org score parameter labels and help texts fully translatable through the i18n label
system (standing rule: every user-visible string must be editable in the translation manager). Currently
score-config.ts hard-codes German label/help strings; the fix is to have the backend emit LABEL KEYS
(like adminFeatures.ts does for nav) and let the frontend resolve them with t(). Do NOT publish.

═══════════════════════════════════════════════════════════════════
1) artifacts/api-server/src/lib/score-config.ts — labels become KEYS
═══════════════════════════════════════════════════════════════════
Replace every plaintext `label:` and `help:` value in SCORE_PROFILES with a label-key STRING (the key
itself, not translated text). Keep key/default/min/max/step untouched. Also change the profile-level
`label`. Use this exact mapping:

  profile.label:                    "score.profile_schema_org"

  breadth_saturation   label:       "score.param_breadth_saturation_label"
                       help:        "score.param_breadth_saturation_help"
  substance_saturation label:       "score.param_substance_saturation_label"
                       help:        "score.param_substance_saturation_help"
  substance_k          label:       "score.param_substance_k_label"
                       help:        "score.param_substance_k_help"
  malus_per_hard_error label:       "score.param_malus_per_hard_error_label"
                       help:        "score.param_malus_per_hard_error_help"
  malus_floor          label:       "score.param_malus_floor_label"
                       help:        "score.param_malus_floor_help"

The ScoreParamDef / ScoreProfile interfaces already type label/help as string — no type change needed.
Nothing else in score-config.ts changes (the GET route already spreads these through to the frontend
unchanged, so the keys arrive verbatim).

═══════════════════════════════════════════════════════════════════
2) artifacts/gaio-analyzer/src/views/admin/ScoreSettingsView.tsx — resolve with t()
═══════════════════════════════════════════════════════════════════
The view currently renders profile.label / param.label / param.help DIRECTLY. Wrap each in t():
  {profile.label}  →  {t(profile.label)}
  {param.label}    →  {t(param.label)}   (also in the aria-label={param.label} → aria-label={t(param.label)})
  {param.help}     →  {t(param.help)}
Because t() returns the key unchanged if no entry exists, this is safe even if a key is ever missing.
Do not change anything else in the view.

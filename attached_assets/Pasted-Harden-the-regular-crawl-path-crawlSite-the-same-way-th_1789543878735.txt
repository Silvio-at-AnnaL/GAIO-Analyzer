Harden the regular crawl path (crawlSite) the same way the explicit-URL path was already hardened, so a
SLOW site (e.g. inden-gmbh.de: pages take 2-3.5s each, some fetches time out from the server, total crawl
can exceed the 10-min watchdog) fails FAST and cleanly instead of grinding until the watchdog kills it —
and so the progress bar moves instead of sitting at 5%. Do NOT touch the frontend or report renderers.
Do NOT publish. Report back before pushing.

Root cause (verified): The normal analysis of a domain runs the `else` branch
`crawlResult = await crawlSite(url, 16)` (analysis-engine.ts ~line 301). crawlSite (crawler.ts ~506) has
NO overall deadline and reports NO intermediate progress. Its main `while (pagesLeft > 0)` loop
(crawler.ts ~701) fetches pages sequentially via fetchWithTiming (15s timeout each). On a slow site,
16 pages × up to 15s = several minutes, so progress stays at 5% until the 10-min watchdog fires. Layer 1
(per-fetch timeout) already works; this adds a batch deadline + progress to crawlSite.

1) crawler.ts — crawlSite: overall deadline + progress callback + timedOut flag
═══════════════════════════════════════════════════════════════════
a) Change the signature to accept an options object (keep backward compatibility — both params optional):
     export async function crawlSite(
       inputUrl: string,
       maxPages = 16,
       opts?: { deadlineMs?: number; onProgress?: (done: number, total: number) => void },
     ): Promise<CrawlResult>
   Define a hard deadline near the top:
     const CRAWL_DEADLINE_MS = opts?.deadlineMs ?? 90_000;   // 90s total for the whole crawl
     const crawlStart = Date.now();
   (90s is generous for 16 normal pages but well under the 10-min watchdog; a genuinely slow site trips
    it in ~1.5 min instead of grinding for 10.)

b) Add a `timedOut` field to CrawlResult (interface ~line 31): `timedOut: boolean;` — initialise it
   `false` in the result object literal (~line 513). Set it true if the deadline breaks the loop.

c) In the main `while (pagesLeft > 0)` loop (~line 701): at the TOP of each iteration, check the
   deadline BEFORE fetching the next page:
     if (Date.now() - crawlStart > CRAWL_DEADLINE_MS) { result.timedOut = true; break; }
   After each successful page push (~after line 755 `pagesLeft--`), report progress:
     opts?.onProgress?.(result.pages.length, maxPages);
   Also add the same deadline check to the EARLY phases that can be slow on a bad site — specifically the
   link-discovery / sitemap-child fetching loops if they iterate many URLs. Keep it simple: the main loop
   check is the priority; if the robots/sitemap/llms probes at the top already have their own short
   timeouts (they call fetchWithTiming with 3000-5000ms), leave those as is.

d) Ensure the result is still well-formed when timedOut is true: return whatever pages were gathered so
   far, with reliability reflecting attempted/succeeded honestly. Do NOT throw — a timed-out crawl that
   got SOME pages should still return them (the analysis can proceed with partial data); a timed-out
   crawl with ZERO pages returns an empty pages array and timedOut:true (the engine decides what to do).

2) analysis-engine.ts — pass deadline + progress, handle the timed-out-empty case
═══════════════════════════════════════════════════════════════════
Replace the two `crawlSite(url, 16)` calls (~line 301 in the else branch; check if there's a second one)
with:
     crawlResult = await crawlSite(url, 16, {
       deadlineMs: 90_000,
       onProgress: (done, total) => {
         state.progress = 5 + Math.round((done / Math.max(1, total)) * 15); // 5→20%
         state.currentModule = "Crawling Website";
         save();
       },
     });
     pages = crawlResult.pages;

The existing `if (pages.length === 0)` block right after (~line 308) already sets status=failed and
returns — GOOD, keep it. But improve its message so it distinguishes the timed-out case from a plain
unreachable case, because Task 2 (the sales-facing error report) will build on this:
     if (pages.length === 0) {

       state.errors.push(
         crawlResult.timedOut

           : (explicitUrls && explicitUrls.length > 0
               ? "Crawl fehlgeschlagen: keine Seite konnte innerhalb des Zeitlimits geladen werden"
               : "Crawl fehlgeschlagen: Die Website konnte nicht abgerufen werden (nicht erreichbar oder blockiert automatisierte Zugriffe)."),
       );
       save();
       return;
     }
Keep the German wording exactly as above — it is user-facing and Task 2 will reuse these signals.
